# Turnlog

Search and replay every coding-agent session you've ever run — locally. A free, MIT-licensed npm CLI (`npx turnlog`) that starts a localhost-only server, indexes Claude Code (`~/.claude/projects/`) and OpenAI Codex (`~/.codex/sessions/`) logs into SQLite + FTS5, and opens a React web UI for full-text search and session replay. Read-only: neither source directory is ever written to. Website: [turnlog.dev](https://turnlog.dev).

Key locked decisions:

- **Distribution is npm CLI + local web UI** — never an Electron app, no code signing, no installers. npm is the update channel.
- **100% local, no telemetry, no accounts.** The app never phones home. This is the brand promise; nothing may violate it. The single optional network touch is a CLI update-available check (opt-out-able) — nothing else.
- **Name is Turnlog.** "Claude" may appear in descriptions ("for Claude Code") but never in product or package names. Lead all copy with *search and replay*, never "logs."
- **Free and open source (MIT).** No accounts, license keys, or payment path — index and open every session with no limits.

## Repo layout & commands

- `src/parser/` — streaming line reader with byte offsets, `normalize.ts` (sniffer + cardinal-rule wrapper), `adapters/v1.ts` (pure function, raw record → `NormalizedRecord`)
- `src/indexer/` — SQLite schema (`db.ts`), incremental `Indexer`, worker-thread driver (`workerDriver.ts` + `worker.ts`), in-process driver for tests/CLI, chokidar watcher
- `src/server/` — hardened `node:http` server, typed API (`api.ts` + `apiTypes.ts`, the contract the web UI imports type-only), serves `web/dist`. Everything is GET except a small POST allowlist (`…/meta`, `…/tags`, `…/reveal`, `…/bookmarks`, `/api/searches`, `/api/prefs`, `/api/maintenance`, `/api/files/open` — exists only when settings.json configures `editorCommand`, and only opens paths in `files_touched` — and `/api/shutdown`); any other POST is 405. Writes only ever touch Turnlog's own index — `~/.claude` is read-only, always.
- `src/cost/pricing.ts` — shipped pricing table; cache writes priced by TTL breakdown (1.25× 5m / 2× 1h)
- `src/export/` — session serializers, all dependency-free: `markdown.ts` (minimal ±line diffs, no diff lib in the server), `html.ts` (self-contained styled page, everything inline, content escaped — logs are untrusted input; the API serves it `Content-Disposition: attachment` so it never renders on the app origin), `redact.ts` (regex scrub of token shapes/emails/home paths, opt-in on both formats). Used by `turnlog export <id> [--html] [--redact] [--from n] [--to n]` and `GET /api/sessions/:id/export?format=&redact=&from=&to=` — `from`/`to` are message idxs and mark the output an excerpt. The web UI drives all of it from one share popover in the replay header.
- `src/mcp/mcp.ts` — `turnlog mcp`: the index as read-only agent memory over a stdio MCP server. Hand-rolled JSON-RPC 2.0 (newline-delimited; no MCP SDK — the zero-dep rule), tools-only surface (`search`, `list_sessions`, `get_session`, `get_messages`, `get_context`, `file_history`) over the same `src/server/api.ts` query functions. In MCP mode stdout is the protocol channel — every diagnostic goes to stderr, never console.log. **Decided 2026-07-27: the MCP surface stays strictly read-only — no write tools, no opt-in flag.** "It cannot write anything" is a guarantee a stranger can verify from the tool list, and the annotation tables are a human curation surface (`is:pinned` must keep meaning "I flagged this"). An agent that wants to remember something writes to its own memory and cites the session id.
- `web/` — npm workspace: the Vite + React viewer. Full-bleed bento visual language, tokens in `web/src/theme.css`, nothing ever loaded from the network. See `web/CLAUDE.md` for the screens, the threading/tolerant-parse rules, and the asset policy.
- `bin/turnlog.cjs` — plain CJS on purpose: it must parse and run on Node versions the ESM build would reject, so it can print the version guard instead of crashing

Commands: `turnlog demo` boots the real UI against `fixtures/corpus` + `fixtures/codex` in a temp data dir (shipped in `files`, so packaging changes there break it). `npm run golden:update` regenerates goldens after an adapter change — review the diff, that's the point of them. Smoke test against real data without touching the user's config: `TURNLOG_DATA_DIR=<scratch> node bin/turnlog.cjs index` (reads `~/.claude/projects`, writes the index to the scratch dir). UI dev loop: `npm run dev` (one command: builds the server, boots API + Vite with a shared token, Ctrl-C stops both; `scripts/dev.mjs`). The Vite proxy injects the token and rewrites Host and Origin (the cross-origin defenses reject the dev origin's port otherwise). `TURNLOG_FAKE_UPDATE=x.y.z` seeds a fake newer version so the CLI line + web update banner render without a published release.

Conventions: any adapter change ships with corpus fixtures + regenerated goldens. Bump `ADAPTER_VERSION` in `src/version.ts` when normalization output changes — it forces a full reindex. Every user-visible change gets a line under `[Unreleased]` in `CHANGELOG.md` (Keep a Changelog format). Cutting a release is its own procedure — **a release IS the version bump reaching `main`** — see the `release` skill before bumping a version. Before declaring anything release-ready: `npm run preflight` (typecheck + lint + build + tests, strict exit codes — never judge a check by piped output), and wait for the `development` CI matrix to go green; the release workflow re-runs the full 3-OS × 2-Node matrix and will not publish past a red leg, so a red development matrix just means a doomed release run later. The server-hardening tests in `test/server.test.ts` are load-bearing; never weaken them. Note: `fetch` can't forge a Host header (undici strips it) — hardening tests must use raw `http.request`. This repo is public: keep strategy, planning, and internal notes out of committed files (`CLAUDE.local.md` is the gitignored place for those).

## Stack

- **CLI/server:** Node 22+ (20 is EOL and better-sqlite3 ≥12.10 ships no prebuilds for it), TypeScript, ESM. Server is bare `node:http` (chosen over Fastify — zero runtime deps beyond better-sqlite3 + chokidar), binds 127.0.0.1 only, serves the built React bundle + JSON API.
- **Indexer:** worker thread (or child process) — JSONL parsing and SQLite writes must never block the API.
- **Data:** better-sqlite3, WAL mode, single writer. FTS5 with `unicode61 tokenchars '_$.'` + `prefix='2 3'`. Message text stored in the DB. Incremental indexing via per-file byte offsets. DB in `~/.config/turnlog/` (XDG on Linux, `%APPDATA%` on Windows).
- **Frontend:** React + TypeScript + Vite, shipped prebuilt inside the npm package. React Query over the local API. react-virtuoso for session lists (virtualization is mandatory), Shiki in a web worker for highlighting.
- **Packaging:** single npm package. No postinstall scripts, ever. Publish with `--provenance` from GitHub Actions — triggered by a version bump landing on `main` (or a hand-pushed matching tag).

## Hard rules

- **Localhost hardening is v1 scope, not optional:** loopback-only bind, random high port, validate `Host`/`Origin` headers against localhost (DNS-rebinding defense), random session token in the opened URL required on every API request, no CORS headers.
- **Parser cardinal rule: never crash, never drop.** Claude Code's JSONL format is undocumented and changes without notice. Unrecognized records are stored with `kind='unknown'` + `raw_json` and rendered as collapsed "unrecognized event" rows. Format churn must be a cosmetic bug, not data loss.
- **Parser architecture:** `RawLine → VersionSniffer → AdapterVN → NormalizedRecord`. Adapters are pure functions in one directory; snapshot-test the whole corpus with golden files. Stream-parse JSONL (sessions run 50–500MB) — never `JSON.parse` a whole file.
- **Threading is a `parentUuid` chain**, not a flat array — branches exist. Sidechain records are subagent runs, rendered as nested collapsible threads. `tool_use` pairs with `tool_result` by ID; results can be enormous — collapse by default. Newer CC also writes Task subagent transcripts to separate files (`<project>/<session>/subagents/*.jsonl`) — indexed as child sessions (`sessions.parent_session_id`), hidden from lists, rolled into the parent's aggregates, and nested in the parent's replay under the Task call that spawned them (anchored by the transcript's opening prompt matching the Task `input.prompt`). **Most multi-child nodes are not branches** — one API response is many lines chained under each other, its `tool_result` lands as a sibling of the next line, and injected meta/system records hang off whatever preceded them. A real branch is what's left after excluding those (same `message_id` as the parent, `tool_result`, bookkeeping kinds): the last child in file order is the live path, earlier siblings are abandoned — nearly always a prompt the user interrupted and retyped. Abandoned rows are dropped from the turn spine (`findAbandonedIdxs`, `src/server/api.ts`) and folded into an "abandoned attempt" block in the replay (`findAbandoned`, `web/src/replay/thread.ts`) — the same rule on both sides; keep them in step.
- **Usage counts once per API response, never per line.** CC writes one JSONL line per content block; every line repeats the same `message.id` and the same `usage` object. The indexer zeroes duplicate lines' usage (cost NULL) via `messages.message_id` — summing per line inflates costs ~2.7×. `isMeta:true` user records are kind `'meta'`, not prompts. A second, independent double-count lives across FILES: resuming copies the whole history into the new session file, so spend dedupes per chain family (`root_uuid` + project, first occurrence of each message uuid wins) — see `getSpend`, which also aggregates messages without joining `sessions` per row, because that join dominated the query.
